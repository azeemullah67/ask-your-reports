# Ask Your Reports

A small .NET 8 demo: type a business question ("Which products earned the least revenue last month?") and get a short
plain-English answer from a SQL database, with the AI restricted to choosing from five pre-approved reports.

The AI never writes SQL. It picks a report name and fills in parameters as JSON; C# validates that JSON
against a whitelist before any query runs, and the query itself is fixed, parameterized SQL written by a developer.

Everything runs offline by default with a free, deterministic **fake** AI client. Two real providers,
Anthropic Claude and Google Gemini, can be switched on by config; both are **off by default**. The Anthropic
client has never been run against its live API, and the Gemini client has been run live once, before the
current summary fix (see [Real provider: Gemini](#real-provider-gemini) and [Testing status](#testing-status)).

All data is fake sample data generated by a seed script.

## What it does

1. You type a question on the single HTML page (or `POST /ask`).
2. The AI client chooses one report and its parameters, returned as JSON:
   `{"report": "worst_products", "parameters": {"period": "last_month", "limit": 5}}`
3. C# validates the JSON: known report, known parameters, correct types, values in range.
   Anything else returns "I couldn't map that question to one of the available reports."
4. The report's fixed SQL runs on a **read-only** SQLite connection with the validated parameters bound.
5. The AI client turns the rows into a one- to three-sentence answer, working from the same formatted values
   the page shows (for example `$1,237.50`).
6. C# checks that answer against the rows (see [Summary check](#summary-check)). If it fails, a plain summary
   built in C# is shown instead, with the note "AI summary failed a check, showing a plain summary".
   The page also shows the report and parameters used, the date range and the rows.

### The five reports

| Report | Parameters |
|---|---|
| `worst_products` | `period`, `limit` (1-20) |
| `top_products` | `period`, `limit` (1-20) |
| `revenue_by_category` | `period` |
| `sales_by_region` | `period` |
| `monthly_revenue_trend` | `months` (1-12) |

`period` is one of `last_7_days`, `last_30_days`, `last_90_days`, `this_month`, `last_month`.
The AI only chooses the name; C# turns it into dates.

## Architecture

```
  Browser (wwwroot/index.html)
      |  POST /ask {"question": "..."}
      v
  AskService ------------------------------------------------------------+
      |  1. ChooseReportAsync(question)                                   |
      v                                                                   |
  ILlmClient                                                              |
      |-- FakeLlmClient (default: keyword matching, no network)           |
      '-- GuardedLlmClient (daily limit, timeout, retries, token logs)    |
              |-- AnthropicLlmClient (official SDK; only if enabled)      |
              '-- GeminiLlmClient (official SDK; only if enabled)         |
      |                                                                   |
      |  raw text (maybe JSON, maybe not)                                 |
      v                                                                   |
  ReportSelectionValidator --- invalid ---> "I couldn't map that question"
      |  valid: report + typed parameters
      v
  ReportRunner --> ReportCatalog (5 fixed SQL queries) --> SQLite (read-only)
      |  rows
      v
  ILlmClient.SummarizeAsync(question, rows) --> answer + rows back to the page
```

| Path | Role |
|---|---|
| `src/AskYourReports/Reports/` | Report catalog (SQL + parameter rules), validator, runner, named periods |
| `src/AskYourReports/Llm/` | `ILlmClient`, fake client, Anthropic and Gemini clients, guard, prompts, options |
| `src/AskYourReports/AskService.cs` | The pipeline; turns every failure into a clear response |
| `src/AskYourReports/Data/SalesDatabase.cs` | Schema and deterministic seed data |
| `tests/AskYourReports.Tests/` | xUnit tests (no network, no API key) |

## Run it in fake mode (free, offline)

Requires the .NET 8 SDK.

```bash
dotnet test                                  # 116 tests
dotnet run --project src/AskYourReports      # then open the URL it prints
```

On first run it creates `reports.db` with 12 products and about 180 days of sales up to yesterday
(delete the file to regenerate it). Try the example buttons on the page, including the one that
deliberately cannot be mapped.

The fake client matches keywords ("worst", "top", "category", "region", "trend", "last month", "top 3"...)
and writes template summaries. It exists to demo and test the pipeline; it does not understand language.

## Real provider: Anthropic

This calls a paid API. Before turning it on:

- Check current pricing and any free tier on Anthropic's site; this README does not quote prices.
- Set a spending limit in the Anthropic Console.
- Consider lowering `Llm:DailyRequestLimit` (default 100 calls per UTC day).

1. Store the key outside the repo, using either option:

   ```bash
   # Option A: dotnet user-secrets (stored in your user profile, loaded in the Development environment)
   dotnet user-secrets set "Anthropic:ApiKey" "<your key>" --project src/AskYourReports

   # Option B: environment variable
   export ANTHROPIC_API_KEY="<your key>"      # PowerShell: $env:ANTHROPIC_API_KEY = "<your key>"
   ```

   Never put the key in `appsettings.json` or any file in the repo.

2. Switch the provider for one run without editing files:

   ```bash
   dotnet run --project src/AskYourReports -- --Llm:Provider=Anthropic
   ```

   Or set `"Provider": "Anthropic"` in `appsettings.json`. If no key is found, the app refuses to start and
   says how to set one.

## Real provider: Gemini

**Live testing so far:** one live test was run on 2026-10-25 with `gemini-3.5-flash-lite`: one question,
2 model calls, no retries. The report choice was correct (`worst_products`, last month) and passed the
validator. The summary showed missing currency formatting ("280" instead of "$280.00") and omitted 3 of
the 5 products returned.

This led to the current change: the model now receives display-formatted values, and a deterministic C#
check replaces any summary that misses a row or contains a number not in the rows. That change is tested
only with simulated model output. **It has NOT been re-tested against the live Gemini API.**

This calls a paid API. Before turning it on:

- Check current pricing and any free tier on Google's
  [Gemini API pricing page](https://ai.google.dev/gemini-api/docs/pricing); this README does not quote prices.
- Check billing for your key on the [Gemini API billing page](https://ai.google.dev/gemini-api/docs/billing),
  and set any budget or spending alerts you want there.
- Consider lowering `Llm:DailyRequestLimit` (default 100 calls per UTC day).

1. Create a key in [Google AI Studio](https://aistudio.google.com/apikey) and store it outside the repo,
   using either option:

   ```bash
   # Option A: dotnet user-secrets (stored in your user profile, loaded in the Development environment)
   dotnet user-secrets set "Gemini:ApiKey" "<your key>" --project src/AskYourReports

   # Option B: environment variable
   export GEMINI_API_KEY="<your key>"         # PowerShell: $env:GEMINI_API_KEY = "<your key>"
   ```

   Never put the key in `appsettings.json` or any file in the repo.

2. Switch the provider for one run without editing files:

   ```bash
   dotnet run --project src/AskYourReports -- --Llm:Provider=Gemini
   ```

   If no key is found, the app refuses to start and says how to set one. Having `GEMINI_API_KEY` set does
   not switch the provider on by itself; `Llm:Provider` must say `Gemini`.

The default model is `gemini-3.5-flash-lite`. If it is not available to your key (HTTP 404), the error
message suggests `gemini-3.8-flash`; switch with `--Llm:Model=gemini-3.8-flash`. The app does not switch
models automatically. `gemini-3.8-flash` has not been checked against the live API.

The choose-report call asks for `application/json` output with a JSON Schema (`responseJsonSchema`);
Gemini's [structured output](https://ai.google.dev/gemini-api/docs/structured-output) supports all the
keywords it uses (`enum`, `required`, `additionalProperties: false`). The summary call asks for plain text.
The same limits, timeout, retries and token logging apply as for Anthropic, and the SDK's own retries are off.

## Settings for the real providers

`Llm` section of `appsettings.json` (any value can also be passed as `--Llm:<Setting>=<value>`):

| Setting | Default | Meaning |
|---|---|---|
| `Provider` | `Fake` | `Fake`, `Anthropic` or `Gemini` |
| `Model` | empty | Empty means the provider's default: `claude-opus-5-5` (Anthropic), `gemini-3.5-flash-lite` (Gemini) |
| `MaxInputTokens` | 4000 | Calls whose estimated prompt is larger are refused before sending |
| `MaxOutputTokens` | 1024 | Per-call output cap (`max_tokens` / `maxOutputTokens`); includes the model's thinking tokens |
| `DailyRequestLimit` | 100 | Model calls per UTC day, counting every retry |
| `Timeout` | `00:00:20` | Per-attempt timeout |
| `MaxRetries` | 2 | Retries for timeouts and transient errors (429, 5xx, network) |
| `RetryBaseDelay` | `00:00:01` | Backoff: 1 s, then 2 s |

Each question makes two model calls (choose, then summarize). Every call is logged with its input and output
token counts and how many of today's calls have been used.

## Design decisions and trade-offs

### Whitelist instead of free SQL

Letting a model write SQL means trusting it with the database: it can produce wrong joins that silently give
wrong numbers, read tables it shouldn't, or be talked into destructive statements by a crafted question.
Here the model only picks from a menu.

- **Five fixed queries** written and reviewed by a developer, with parameters bound, never concatenated.
- **Strict validation in C#** before anything runs: unknown reports, unknown or duplicate fields, wrong types
  (`"5"` or `2.5` for an integer) and out-of-range values are rejected. The validator does not trust the
  API's structured-output schema either.
- **Read-only connection** for reports, as a second line of defence.
- **Named periods instead of dates**, so the model never does date arithmetic.

The trade-off is flexibility: questions outside the five reports cannot be answered. Adding a report means
writing its SQL and parameter rules, which is deliberate: each new capability is reviewed code.

### Cost controls

- Fake client by default; the paid client needs explicit config and a key.
- Per-call input cap (checked before sending) and output cap (`max_tokens`).
- Per-day call limit, counting retries, with a clear message when it is hit.
- Anthropic: `low` effort, since choosing a report is simple classification. Gemini: the model's default
  thinking settings (not tuned).
- Both SDKs' built-in retries are disabled so retries are not doubled (SDK retries x our retries).
- Questions longer than 300 characters are rejected before any model call.
- Token counts are logged per call so spend can be checked against the provider's dashboard.

### Failure handling

| Situation | What the user sees | HTTP |
|---|---|---|
| Model returns invalid JSON, an unknown report or bad parameters | "I couldn't map that question to one of the available reports." plus the reason | 422 |
| Question empty or too long | A request to rephrase | 400 |
| Daily limit reached | "The daily AI request limit (N calls) has been reached. It resets at midnight UTC." | 429 |
| Timeout or provider errors after 2 retries; bad key; billing problem (402); unknown model (404); refusal, blocked, empty or truncated (output cap) response | "The AI service is unavailable right now. Please try again shortly." The specific reason (for example "billing problem (402 Payment Required)") is in the response's `detail` | 503 |
| Report ran but the summary call failed | The rows, with a note that the written summary is unavailable | 200 |
| AI summary misses a row or contains a number not in the rows | A plain summary built in C#, the note "AI summary failed a check, showing a plain summary", and the reason in `detail` | 200 |

Timeouts and transient errors (429, 5xx, network) are retried with exponential backoff; permanent errors
(400, 401, 402, 403, 404) are not, because retrying cannot fix them and would cost more.

### Summary check

The report choice is validated before any SQL runs; the written summary is checked after it is generated.
Both work on the same display-formatted values (`ReportFormatting`): revenue in US dollars with two
decimals, counts with thousands separators. The page, the fake client and the prompt all use these strings.

The check (`ReportSummaries.TryCheck`) fails a summary if:

- the report returned 5 rows or fewer and any row's name (product, category, region or month) is missing, or
- it contains a number that is not exactly one of the formatted values in the rows. "280" fails where the
  row says "$280.00". The only other numbers allowed are the period text copied exactly
  (`last month (2026-09-01 to 2026-09-30)`) and the row count (for "top 5"). Digits inside names, such as
  "Paper Filters (100)", are ignored.

When it fails, the model's text is not shown. The answer is a plain summary built in C# from the formatted
rows, the response has `summaryChecked: false` and the reason in `detail`, and the page shows "AI summary
failed a check, showing a plain summary". The model is not called again, because a retry costs money and
may fail the same way.

| `summaryChecked` | Meaning |
|---|---|
| `true` | The model's summary passed the check and is shown |
| `false` | It failed; the plain C# summary is shown |
| `null` | No summary was generated (for example the summary call failed) |

116 xUnit tests, all using the fake client or a fake HTTP handler. **No test calls a paid API or needs a key.**

| Reports | Each of the five reports returns rows on the seed data; worst sellers last month sorted and dated correctly |
| AskService (fake client) | Valid pick end to end; invalid JSON, unknown report and bad parameters return "couldn't map"; empty and overlong questions; a summary that passes the check is shown; a failing or empty summary is replaced by the plain summary with `summaryChecked: false` and no second model call |
| Formatting | Revenue as USD with two decimals (including whole and zero amounts), counts with thousands separators, text unchanged, every display row formatted by column |

| `/ask` endpoint | In-memory app over HTTP: answered question, unmappable question (422), empty question (400), page served |

**Not tested yet:**

- **The Anthropic client against its live API.** It has never made a real call; it is tested against a
  simulated HTTP server only.
- **The Gemini client since the summary fix.** It was run live once, before this change (see
  [Real provider: Gemini](#real-provider-gemini)). The formatted-rows prompt and the summary check have been
  tested only with simulated model output, not re-tested live, so it is not known how often a real Gemini
  summary now passes the check.
- Answer quality from a real model, beyond the C# checks on its report choice and summary.
- The page on a real phone. The layout was checked manually in desktop Chromium resized to 1280, 390 and
  320 px wide (no page overflow; the results table scrolls sideways to its last column with the mouse wheel
  and with the keyboard). That checks the layout, but it does not prove touch swiping works on a real
  phone, and Safari and Firefox were not tried.
- The page's JavaScript in automated tests. xUnit only checks that the page is served; the browser checks
  above were manual.
- Concurrent load.

## Known limits

- **Five reports only.** Anything else gets "couldn't map", by design.
- **Fake client is keyword matching**, not language understanding. Phrasings it doesn't know fail to map.
- **The summary check is narrow.** It checks names (for 5 rows or fewer) and numbers, not meaning: a summary
  that names every row and quotes correct values but draws a wrong conclusion ("sales grew") still passes.
  Numbers written as words ("five") are not checked. With more than 5 rows, only numbers are checked. The page
  shows the rows next to the answer for that reason.
- **A strict check may reject reasonable summaries** (for example "$1237.50" without the comma, or a date
  written differently from the period text). They fall back to the plain summary rather than being shown.
- **Daily limit is in memory**: it resets when the app restarts and is per process, not per user. With no
  auth, anyone who can reach the page shares the quota. Not suitable for public deployment as is.
- **Input cap is an estimate** (about 3 characters per token), not an exact token count.
- **Worst-case latency**: with a 20 s timeout and 2 retries, one model call can take about 63 s, and each
  question makes two calls.
- **Model refusals and blocked responses** are shown as "unavailable"; there is no automatic fallback model.
- **Shared prompt**: both providers get the same system prompt, which describes the JSON shape in words.
  Google advises not repeating the schema in the prompt; this was not tuned for Gemini.
- **Permanent provider errors** (bad key, billing, unknown model) are returned in the response `detail` but
  not written to the log; only retried failures are logged.
- **Dates**: report periods use the server's local date; the daily limit resets at midnight UTC.
  Seed data stops at yesterday, so `this_month` is empty on the 1st.
- **user-secrets** are loaded only in the Development environment (the default for `dotnet run`);
  use the environment variable elsewhere.
- **SQLite with fake data.** No auth, no Docker, no cloud deployment.
